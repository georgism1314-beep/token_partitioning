回顾：上周汇报（token-id 随层下降）

现象

L0 FFN 几乎直接读词嵌入相关的 token 信号，上下文还没进来。训练开始后，层越深，FFN 激活方差里由「当前 token 是什么」决定的比例越小、由上下文决定的比例越大——这不等于「深层不需要 token 信息」。最后一层不再下降，L31 与 L24 基本持平。step 1k 全层跳升，之后深层回落、5k+ 平台。

解释

Olmo-3 后置归一化：hₗ = eₜ + Σₖ₍ₖ₌₀..ₗ₋₁₎ (aₖ + mₖ) + aₗ；attention / FFN 输入不做 norm，只把输出 RMSNorm 后加回残差。FFN 读到的是全部写入块的累加，token-id η² ≈ 各写入块 η² 的方差加权平均；注意力是唯一跨位置搬运信息的操作，第 0 层之后注意力写入以上下文为主，浅层的 token 信号在加权平均里被稀释。1k 跳变来自 L0 注意力变成 token 特异；基座浅层增益很小、嵌入占比大，但 L0 神经元 η² 仍只有 ~0.48。

本周一：嵌套 n-gram 分解 step 10k

现象

把「上下文」拆成局部 n-gram：η²(tok) + Δ(prev|tok) + Δ(prev2|bigram) + 剩余 = 1。训练后 L0 几乎全是 tok（Δ(prev|tok) ≈0）；从 L4 起 prev 增量明显，L4–L8 最高（step10k ~0.14–0.15），再往深缓慢下降。trigram 相对 bigram 的增量更小且随层/步数几乎不涨（峰值 ~0.05）。深层剩余仍很大（step10k L31 剩余 0.77）。贪心每轮按 (ckpt, layer, neuron) 重算：第一步几乎总是选 tok（98–100%）。

解释

分组：tok ⊂ bigram ⊂ trigram 严格嵌套；prev 是 bigram 按「前一个 token」粗化。bigram = 两折都出现过的最高频 2 万个 (prev, tok)，其余退回 tok 组；trigram 同理叠在高频 bigram 上。Δ(prev|tok) = η²(bigram)−η²(tok) 量的是「给定当前 token 后，前一个 token 还多解释多少」——深层「上下文」里有一块是局部二元组，但不是全部。trigram 增量不随层深变大，是因为：条件信息量相对 bigram 本来就小；覆盖率只有约一半；更长程上下文进剩余项。神经元读到的上下文远比「前两个 token」细。

本周二：字符类 + 上下文 POS

现象

字符类（~18 类，只看 token 字符串）和 spaCy UPOS（对齐到模型 BPE）在 token-id 之上几乎不再多解释方差。Δ(POS|tok) 中位数只有 0.006–0.013，约为 Δ(prev|tok) 的十分之一；所有层、所有 ckpt 上 η²(POS) 从未超过 η²(tok)。pos_multi（冲突 token 单独 MULTI）前三位小数不变。H(POS|token-id)=0.46 bit，相对 H(POS)=3.8 bit，约 88% 的 POS 信息已被 token-id 决定。

解释

字符类是 token-id 的粗化（tok 严格细分 charclass）；tok×POS 格子是 tok 的细分。POS 上下文相关，但同一 token 的 POS 变化有限，所以给定 token 后再看 POS 几乎不增解释力。神经元从上下文拿到的信息比「名词还是动词」细得多——形状上 Δ(POS|tok) 与 Δ(prev|tok) 一样在 L4–L8 略高，但幅度小一个数量级。训练动态也一致：粗粒度（POS / 字符类）在 1k 峰值更高，之后被更细的 token 与局部 n-gram 取代。

方法要点（本周落地）

激活缓存 cache_acts.py：12 ckpt（step0..10k + 基座）× 层 {0,4,8,16,24,31}，bf16 存成 int16 npy，共 2.9 TB。分解脚本只读缓存：factor_decomp.py（tok/prev/bigram/trigram）、pos_tags.py + pos_decomp.py（字符类 / POS）。

分组都要求两折都出现（cross-fit）；稀有格子退回父组，保证嵌套。bigram 覆盖 78.8%、trigram 覆盖 49.7%、tok×POS 覆盖 97.2%（有 ≥2 个 POS 格子的 token 覆盖 48.8%）。
